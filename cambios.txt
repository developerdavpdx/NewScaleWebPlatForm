1. CONTEXTO GENERAL
------------------------------------------------------------------------
- Proyecto: PTM NewScale (portal web de planta).
- Tecnologia: ASP.NET MVC 5 sobre .NET Framework 4.8 (Visual Studio).
- Base de datos: SAP HANA Cloud, consumida a traves de una Web API externa
  (el portal solo hace peticiones HTTP a esa API).
- API: C:\Paradox\PTM\DEVELOPMENT\NEWSCALE\NewScaleWebApi (ASP.NET Core).
  El usuario autorizo ajustar la API cuando el portal lo requiera
  (28/10/2026). API local: https://localhost:7227
- Servidor local: IIS Express en https://localhost:44390
- Raiz del repo: NewScaleWebPlatForm
  - PTM.sln
  - PTM/            -> proyecto web (Controllers, Views, Scripts, Styles)
  - packages/       -> paquetes NuGet
  - .vs/            -> cache de Visual Studio (NO versionar)

- El layout fija <title>PTM NewScale</title>, por lo que ViewBag.Title
  no cambia el titulo de la pestana del navegador.
- La sesion debe tener Session["Rol"]; sin ella el layout lanza
  NullReferenceException al entrar a cualquier vista.


2. OBJETIVO DEL REDISENO
------------------------------------------------------------------------
Modernizar visualmente las vistas con un lenguaje unico, tomando como
modelo la vista de Ordenes de Fabricacion.

Reglas:
- Solo se toca presentacion (vistas .cshtml, CSS y JS de la vista).
- NO se tocan controladores, endpoints, ni logica de negocio.
- Se conservan todos los IDs y funciones que usa el JavaScript
  (sumTotal, SumScrapKG, #search, #btn21, verLinea, emailreporte, etc.).
- La validacion visual la hace el usuario en el navegador.


3. SISTEMA DE DISENO ACORDADO
------------------------------------------------------------------------
- Fuente: Nunito (ya cargada en _Layout.cshtml).
- Color primario: #0058A1 (azul corporativo).
- Titulo de pagina: texto en mayusculas con barra azul a la izquierda
  (border-left de 5px) y subtitulo en gris.
- Contadores: "pills" redondeadas (ej. "11 registros").
- Tarjetas: fondo blanco, radio 12px, sombra suave.
- Header de seccion: fondo #eef4fb, texto azul, icono a la izquierda.
- Header de tabla: fondo #eef4fb, texto azul, borde inferior azul,
  SIN sombra (se neutraliza Flje.css con !important).
- Celdas: centradas, fuente ~13.4px, filas de ~50px.
- Botones: alto 38px, radio 8px, variantes primary / outline / ghost.
- Badges de estado: fondo suave (verde #eaf6e8 / rojo #fdecec) en lugar
  de bloques solidos con texto blanco.
- DataTables: interfaz en espanol (Mostrar N registros, Buscar,
  Mostrando X a Y de Z registros, paginacion Primero/Anterior/...).
- Modales: sistema comun en Styles/Modales.css (header con degradado
  azul, body, footer con Cancelar/Confirmar).
- Iconos: el layout carga Font Awesome 4.7 (Content/font-awesome.min.css).
  Usar SOLO nombres de FA4 (fa-clock-o, fa-bar-chart, fa-tachometer,
  fa-balance-scale, fa-info-circle, fa-calendar, fa-times, fa-save,
  fa-refresh). Los nombres de FA5/FA6 (fa-clock, fa-chart-column,
  fa-gauge-high, fa-weight-scale, fa-circle-info, fa-calendar-day,
  fa-xmark, fa-floppy-disk) no existen en esa hoja y se ven en blanco.

6. CORRECCIONES TECNICAS APLICADAS
------------------------------------------------------------------------
- Producto Terminado / filtradoHistorialPesadas():
    Faltaba "return" despues del aviso de fecha vacia, por lo que la
    peticion se disparaba igual. Corregido en los dos bloques de corte.

- Producto Terminado / emailreporte():
    Enviaba tambien la columna del boton de detalle. Ahora usa
    row.slice(1), igual que las exportaciones a Excel y PDF.

- Producto Terminado / id="btnDetails" duplicado:
    Se generaba un id repetido por fila (HTML invalido). Ahora se usa
    la clase .pt-row-btn y la delegacion de eventos es por clase.

- Producto Terminado / NaN en KPIs:
    Cuando no habia registros, % Sobrepeso, % Eficiencia y % Scrap
    mostraban NaN. Se agregaron guardas de division por cero.

- Modales / bloqueo de scroll:
    El CSS de Bootstrap cargado no define .modal-open; se agrego
    body.modal-open { overflow: hidden; } en ProductoTerminado.css.

- Modales de Detalle de linea:
    Se corrigio el cierre por X, por boton y por clic en el fondo,
    liberando siempre el scroll del body.

- Cache-buster:
    CSS y JS propios se referencian con
    ?v=@System.IO.File.GetLastWriteTime(...).Ticks
    para evitar que el navegador sirva versiones viejas.

- Historial de Pesadas / filtradoHistorialPesadas() y GetHistorialWeight():
    Igual que en Producto Terminado, faltaba "return" en los avisos de
    fecha vacia, asi que la peticion se disparaba de todos modos.
    Corregido en los dos bloques de validacion (corte y turno).

- Historial de Pesadas / GuardarEdicion():
    Los "return" estaban comentados: sin comentario, linea o codigo se
    seguia con el guardado. Ahora cortan la ejecucion y apagan el loader.

- Historial de Pesadas / NaN en "Sobrepeso":
    pesoEstandar = 0 (SKU sin peso minimo) producia NaN. Se agrego la
    misma guarda de division por cero que en Producto Terminado.

- Historial de Pesadas / ObtenerEmail():
    La tercera columna del modal de Correo repetia el nombre completo.
    Ahora muestra sapemail[x].email, como en Producto Terminado.

- Historial de Pesadas / contadores:
    Se agregaron los pills "N registros" y "N seleccionados". Se
    actualizan en drawCallback y al marcar/desmarcar checkboxes, por lo
    que respetan la paginacion y los filtros.

- Historial de Pesadas / checkBoxSeleccionar():
    "Seleccionar todos" ahora llama a actualizarSeleccionados() para
    refrescar el contador en el mismo instante.

- Historial de Pesadas / EnviarASap():
    El boton ahora conserva su icono: el texto "Enviando..." se aplica
    al span .hp-btn-label en lugar de borrar todo el contenido. Si el
    boton no existe (vista Reportes) ya no lanza excepcion.

- Historial de Pesadas / errores de red:
    Las ramas else y catch de GetHistorialWeight y del filtro estaban
    vacias. Ahora muestran un aviso con iziToast para que el usuario
    sepa que la consulta fallo.

- Historial de Pesadas / body.modal-open:
    Se agrego tambien en HistorialPedida.css, porque este layout no
    define la clase y el fondo seguia scrolleando con el modal abierto.

- Dashboard / clases inexistentes en las tarjetas KPI:
    Usaba border-bottom-dark/danger/success/warning, text-xs y
    text-gray-800 (de SB Admin 2), que no existen en el Bootstrap 5
    cargado. Las 4 tarjetas se veian iguales, sin color de acento.
    Ahora el color va por clase propia (.inicio-kpi-*) y la tipografia
    esta definida en Inicio.css.

- Dashboard / fila de objetivos desbordada:
    Era flex-nowrap con etiquetas de 24px: necesitaba ~842px en un
    contenedor de ~697px. Ahora es flex-wrap con etiquetas de 12px,
    inputs de 118px y el boton alineado a la derecha.

- Dashboard / contenido encajonado:
    Habia un .container dentro del container-fluid del layout, asi que
    la vista medía ~673px contra ~1117px del resto. Ahora ocupa el ancho
    completo, como las demas vistas.

- Dashboard / id="SobrePeso" duplicado:
    Se repetia en la tarjeta de PPVC y en la de INY. Renombrado a
    lblSobrepesoPPVC / lblSobrepesoINY.

- Dashboard / las graficas dependian de INY:
    CrearGraficos() solo se llamaba en el success de la peticion INY.
    Si INY fallaba, PPVC tampoco se dibujaba. Ahora la carga usa
    Promise.allSettled, PPVC se pinta aunque INY falle y, en planta 1,
    las peticiones y graficas de INY se omiten por completo.

- Dashboard / if (jsonData.status = 200):
    Era una asignacion, no una comparacion: siempre entraba al success.
    Corregido a != 200 con throw.

- Dashboard / Highcharts.setOptions repetido:
    Se llamaba antes de cada grafica y la ultima configuracion ganaba
    globalmente. Ahora hay un solo tema (aplicarTema) y las graficas se
    generan con funciones reutilizables (volumen, sobrepeso, eficiencia,
    scrap), destruyendo la instancia anterior antes de redibujar.

- Dashboard / guardar objetivos recargaba la pagina:
    Hacia location.reload() a los 2s. Ahora recarga solo los datos y
    redibuja las graficas en sitio.

- Dashboard / errores silenciosos:
    Los catch solo hacian console.log y el loader podia quedarse
    prendido. Ahora se avisa con iziToast, el loader siempre se apaga y
    se muestra un aviso de "sin produccion" cuando todo esta en cero.

- Dashboard / indicadores nuevos:
    Pills de turno, planta y hora de actualizacion; contador de lineas
    con produccion; badge "Dentro/Fuera del objetivo" para sobrepeso y
    scrap; boton Actualizar y auto-refresh cada 5 minutos (solo con la
    pestana visible).

- Taras / datosfinales compartido:
    Una sola variable guardaba el ultimo excel cargado, sin importar la
    seccion. Si se cargaba el archivo de Kg/Hora y luego se presionaba
    "Confirmar actualizacion" en Taras, se enviaban los datos de
    Kg/Hora al endpoint de taras (y viceversa). Ahora cada seccion usa
    su propio arreglo (datosTaras / datosKgHora) y avisa si se intenta
    confirmar una seccion sin archivo cargado.

- Taras / loader atorado:
    Los XHR no tenian onerror, asi que un fallo de red dejaba el loader
    prendido. Ahora todos los catch apagan el loader y avisan con
    iziToast.

- Taras / "NaN" en la tara:
    parseFloat(...).toFixed(3) convertia celdas vacias o no numericas en
    "NaN". Ahora se respeta el valor original cuando no es numero.

- Taras / textos con encoding roto:
    El toast de taras decia "Actualizaci?n" (caracter invalido en el
    archivo). Se reescribio el JS con acentos correctos.

- Taras / DataTables en ingles:
    Las dos tablas no tenian idioma ni estado vacio. Ahora usan el mismo
    objeto en espanol que el resto de las vistas ("Mostrar N registros",
    "Sin registros para mostrar", "Ultimo", etc.).

- Correos (modal global) / "Error: SyntaxError: undefined is not valid JSON":
    getCorreosTXT() hacia JSON.parse(jsonData.data) sin revisar el status.
    Cuando el controlador responde 400 no manda "data", asi que el parse
    reventaba y el usuario solo veia un error tecnico. Ahora se valida el
    status y, si no hay lista, la tabla queda vacia con un aviso claro.

- Correos / planta2 nunca se asignaba:
    Se declaraba "let planta2" pero jamas recibia valor, asi que las tres
